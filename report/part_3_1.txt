3.1. Развёртывание Milvus Standalone
Практическая реализация выполнена на Milvus в режиме Standalone: все компоненты
(Proxy, координаторы, узлы обработки, etcd и объектное хранилище) работают на одном
Docker-хосте, что достаточно для задач разработки и учебного проекта.

3.1.1. Требования и установка Docker Desktop
Используется Docker Desktop для Windows (Linux-контейнеры). После установки Docker Desktop
запускается, и в разделе Containers проверяется отсутствие активных контейнеров.
Проверка готовности движка выполняется командой docker version.

3.1.2. Запуск Milvus Standalone из репозитория проекта
Развёртывание выполняется не сторонним скриптом, а файлом docker-compose.yml из корня
репозитория проекта. Стек включает четыре сервиса: Milvus standalone, Attu (веб-интерфейс),
etcd (метаданные) и MinIO (объектное хранилище).

Запуск:

docker compose up -d

Состав стека (образы):

    milvus-standalone | milvusdb/milvus:v3.0.1
    attu              | zilliz/attu:v3.0.1
    milvus-etcd       | quay.io/coreos/etcd:v3.5.25
    milvus-minio      | milvusdb/minio:RELEASE.2024-12-18T13-15-44Z

Порты: 19530 — подключение клиентов по gRPC, 9091 — метрики и проверка состояния,
13000 — веб-интерфейс Attu, 9000/9001 — объектное хранилище.

Проверка работоспособности:

    docker compose ps                  # все сервисы Up, у milvus-standalone статус healthy
    curl http://127.0.0.1:9091/healthz # ответ: OK

Подключение и версия сервера:

    server version: 3.0.1

3.1.3. Веб-интерфейс Attu
Управление и просмотр данных выполняются через Attu: http://127.0.0.1:13000.
При первом входе создаётся администратор Attu (admin / AttuDemo123!), затем в форме
Connect указывается соединение с Milvus: host milvus, port 19530, user root,
password MilvusDemo123. В разделе Overview отображаются версия сервера (3.0.1),
режим развёртывания (Standalone) и число коллекций.

3.1.4. Включение авторизации
Авторизация включается конфигурацией docker/milvus-user.yaml, которая монтируется в
контейнер Milvus:

    common:
      security:
        authorizationEnabled: true
        defaultRootPassword: MilvusDemo123

Ключ defaultRootPassword должен находиться внутри секции common.security, иначе пароль
не применяется и сервер принимает только значение по умолчанию. Открытый доступ без
авторизации не используется, поскольку требуется для RBAC (раздел 3.5).

Проверка авторизации:

    root / MilvusDemo123  ->  подключение выполнено
    root / неверный пароль ->  отказ: Fail connecting to server, illegal connection params
